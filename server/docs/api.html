TokCar 가족 서버 API 명세

차량 앱(Kotlin)과 폰 앱(Flutter)이 같이 쓰는 형식. 1단계 범위는 가계정 2개로 로그인하고, 친구 목록을 보고, 방 하나에서 대화 · 현재 위치 · 경로 공유 · 「이 방에서 간 곳」을 주고받는 데까지.

조회 · 기록REST
보내기 · 실시간순수 WebSocket + JSON
서버Java 21 · Spring Boot 4
저장DB(H2 → RDS) + 서버 메모리

User users

Friend friendships users

Place

현재 위치 · 출발 · 목적지 · 「이 방에서 간 곳」이 모두 이 모양. 출발은 name이 빈 글일 수 있다.

3REST

로그인

POST/api/auth/login
요청 { "loginId": "papa", "password": "…" }
응답 200 { "token": "…", "me": { "id": 1, "loginId": "papa", "name": "아빠", "profileImageUrl": null } }
  • 틀리면 401 BAD_CREDENTIALS(left 포함), 5번째에 423 LOCKED. 맞으면 실패 횟수 0으로. 없는 아이디는 left 없이 BAD_CREDENTIALS만.
  • 1단계에는 잠김을 푸는 화면이 없어서, local 프로필은 서버를 켤 때 가계정의 실패 횟수를 0으로 되돌린다.
POST/api/auth/logout

토큰을 버린다. 그 토큰으로 열린 WebSocket도 닫는다. 응답 204.

방 만들기 · 초대 · 나가기

POST/api/rooms
요청 { "name": "", "memberIds": [2, 3] }
응답 201 Room   ← 만든 방(내가 보는 모양)
  • 나 + 고른 친구로 방을 만든다. memberIds 는 1명 이상, 모두 내 친구여야 한다(아니면 NOT_FRIEND). 한 방 최대 50명.
  • name 이 비면 친구 이름을 이어 붙인다(「민지, 엄마」, 30자까지).
  • 서버가 안내 글(SYSTEM)을 남긴다: 「아빠가 방을 만들었어요 · 민지, 엄마 초대」.
POST/api/rooms/{roomId}/members
요청 { "userIds": [5] }
응답 200 Room   ← 바뀐 방
  • 방 멤버가 자기 친구 중 방에 없는 사람을 넣는다(멤버가 아니면 NOT_MEMBER, 이미 있으면 ALREADY_MEMBER).
  • 안내 글: 「민지가 엄마를 초대했어요」.
  • 새로 들어온 사람도 들어오기 전 대화를 볼 수 있다(카카오톡은 안 보임 — 바꿀지 정해야 함, 8절).
DELETE/api/rooms/{roomId}/members/me

나가기. 응답 204. 그 방에 내 경로 공유가 진행 중이면 STOPPED로 끝내고, 안내 글 「아빠가 나갔어요」를 남긴다. 남은 사람이 없어도 방 기록은 지우지 않는다.

4WebSocket

연결

GET /ws (헤더 Authorization: Bearer <token>). 토큰이 틀리면 연결을 받지 않는다(HTTP 401).

  • 한 사람이 여러 기기(차 + 폰)로 동시에 붙을 수 있다. 서버는 그 사람의 모든 연결에 보낸다.
  • 앱은 25초마다 WebSocket ping. 서버는 60초 동안 아무것도 안 오면 연결을 닫는다.
  • 끊기면 1 → 2 → 4 → … 최대 30초 간격으로 다시 붙고, 붙은 뒤 방마다 GET messages?after=<마지막 id>로 빠진 것을 채운다.
  • 차량 앱은 푸시(FCM)를 못 받을 수 있어(구글 서비스 없음) 실시간은 이 연결로만 받는다.

프레임

{ "type": "text.send", "ref": "c-17", … }
  • type: 무슨 일인지.
  • ref: 앱이 정하는 임시 번호. 서버가 ack · error에 그대로 돌려줘서 「보내는 중」 말풍선을 진짜 메시지로 바꾼다. 응답이 필요 없는 프레임은 생략.

앱 → 서버

type내용서버가 하는 일
text.sendroomId, text(1~1000자)DB 저장 → 보낸 연결에 ack, 방 전원에게 message.new
location.sendroomId, location(Place)DB 저장 → ack + message.new
route.startroomId, from, dest, live?DB 저장(state = ACTIVE) + live 메모리 → ack + message.new
route.liveroomId, carLat, carLon, remainSec, pct, etaAt, traffic?메모리만 덮어씀 → 방 전원에게 route.live. DB 안 건드림

  • 한 사람은 한 방에 진행 중(ACTIVE) 경로 공유를 하나만 가진다. 있는데 route.start를 보내면 error ROUTE_ACTIVE. route.live · route.dest · route.end는 「이 방의 내 진행 중 공유」에 적용되고, 없으면 error NO_ACTIVE_ROUTE.
  • route.live는 같은 공유에 2초에 한 번까지만 반영(더 자주 오면 마지막 것만). 차량 앱은 지금처럼 5초마다 보내면 된다.
  • DB에 쓰는 일은 시작 · 목적지 변경 · 끝, 세 번뿐. 차 위치는 디스크에 남지 않는다.

5흐름: 안내 · 경로 공유

sequenceDiagram
    participant C as 차량 앱 (아빠)
    participant S as 서버
    participant P as 폰 앱 (민지)
    C->>S: POST /rooms/1/places (안내 시작한 곳)
    S-->>C: 200 [이 방에서 간 곳 3개]
    C->>S: route.start (from, dest, live)
    Note over S: DB 저장 ACTIVE + 메모리 live
    S-->>C: ack (message 1024)
    S-->>P: message.new (경로 공유 카드)
    loop 5초마다
        C->>S: route.live (차 위치, 남은 시간, traffic)
        Note over S: 메모리만 덮어씀
        S-->>P: route.live (카드 막대 · 지도 마커)
    end
    P->>S: read (msgId 1024)
    S-->>C: read (userId 2, msgId 1024)
    Note over P: 지도 보기를 열면 폰이 직접
네이버 Directions (차 위치 → dest)
    C->>S: route.end (ARRIVED)
    Note over S: DB state · endedAt, 메모리 live 지움
    S-->>P: message.updated (도착)

8구현 메모

  • route.start가 이미 진행 중이면 · 진행 중 공유가 없으면 WebSocket error(ROUTE_ACTIVE · NO_ACTIVE_ROUTE).
  • route.live는 받자마자 메모리에 덮어쓰고, 같은 공유는 2초에 한 번만 전달. 그 사이 값은 2초 뒤 마지막 것 하나로.
  • 메시지를 보내면 보낸 사람의 last_read_msg_id도 그 메시지로 올라간다(내 메시지는 읽은 것).
  • 서버 코드 · 실행 방법: server/README.md.
  • 정해야 할 것: 초대받은 사람이 들어오기 전 대화를 볼지(지금은 보임). 안 보이게 하려면 room_members 에 「들어온 때의 마지막 메시지 id」를 두고 그 뒤 것만 준다.
