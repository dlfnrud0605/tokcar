TokCar 가족 서버 ERD

앱 전체 기능(가입 · 친구 · 방 · 대화 · 위치 · 경로 공유 · 푸시)을 기준으로 잡고, 실시간으로 계속 바뀌는 값은 DB에 두지 않으며, 단계마다 만들 테이블을 표시했다. id는 모두 서버가 매기는 숫자(BIGINT). DB는 PostgreSQL(AWS RDS). 로컬은 H2를 PostgreSQL 모드로. 스키마는 서버의 Flyway V1__init.sql.

1단계가계정 · 친구 목록 · 대화 · 위치 · 경로 공유 2단계가입 · 친구 추가 · 방 만들기 · 푸시 선택서버에 둘지 정해야 함

테이블

users 1단계

계정. 로그인 아이디는 id로 쓰지 않음(바꿀 수 있고, 가족에게 보이지 않게).

idPKBIGINT자동 증가
login_idUKVARCHAR(20)로그인 아이디(소문자)
password_hashVARCHAR(100)BCrypt. 원문 저장 안 함
phone_e164UKVARCHAR(16)+821012345678. 번호 하나당 아이디 하나
countryCHAR(2)KR 등
nameVARCHAR(20)보이는 이름
status_msgVARCHAR(60)상태 메시지(친구 목록)
profile_image_keyVARCHAR(200) NULL프로필 사진 파일 위치(로컬은 서버 폴더, AWS는 S3 키). 전체 URL이 아니라 키만 저장. 없으면 NULL → 앱이 기본 그림
failed_loginsINT연속 실패. 5면 잠김
created_atTIMESTAMP

rooms 1단계

대화방. 1단계는 가계정 둘이 든 방 하나만 미리 만들어 둠.

idPKBIGINT
nameVARCHAR(30)우리 가족
created_byFKBIGINTusers.id
last_msg_idBIGINT방 목록 정렬용(최신 대화 순). 메시지 저장 때 같이 갱신
created_atTIMESTAMP

room_places 1단계

차량 앱 목적지 창의 「이 방에서 간 곳」. 이 방에서 경로 안내를 시작한 곳을 방마다 최대 3개. 순서는 id로: 새로 넣으면 id가 가장 커지고, 이미 있는 곳을 다시 안내하면 지우고 다시 넣어 맨 위로 올림. 4개째면 id가 가장 작은 것을 지움.

idPKBIGINT
room_idFKBIGINTINDEX(room_id, id): ORDER BY id DESC = 최신순
name · addrVARCHARUNIQUE(room_id, name, addr): 같은 곳은 한 줄만
lat · lonDOUBLE목적지로 다시 고를 때 씀

room_members 1단계

누가 어느 방에 있는지 + 어디까지 읽었는지. 읽음을 메시지마다 따로 저장하지 않음.

room_idPK FKBIGINTrooms.id
user_idPK FKBIGINTusers.id. INDEX(user_id): 내 방 목록
last_read_msg_idBIGINT여기까지 읽음. 안 읽은 사람 수 = 이 값이 메시지 id보다 작은 멤버 수
joined_atTIMESTAMP들어오기 전 메시지는 안 보이게 할 때 씀

messages 1단계

대화 한 줄. 모든 종류가 같이 쓰는 칸만 둠. 종류별 내용은 아래 두 테이블(JPA @Inheritance(JOINED)와 같은 모양).

idPKBIGINT전체에서 커지는 값(순서 = id)
room_idFKBIGINTINDEX(room_id, id): 방의 최신 N개 · 이후 것
sender_idFKBIGINT NULL시스템 안내면 NULL
kindVARCHAR(10)TEXT(말풍선) · LOCATION(현재 위치 카드) · ROUTE(경로 공유 카드) · SYSTEM(안내)
textVARCHAR(1000) NULLTEXT · SYSTEM
created_atTIMESTAMP

message_locations 1단계

「내 위치 보내기」로 보낸 그 순간의 위치. messages(kind = LOCATION)와 1:1. 보낸 뒤 안 바뀜. [지도 보기]에서 이 좌표에 마커를 찍음.

message_idPK FKBIGINTmessages.id
place_nameVARCHAR(60)구 · 동 이름(비면 주소로)
place_addrVARCHAR(120)전체 주소
lat · lonDOUBLE보낸 지 1년(messages.created_at 기준)이 지나면 이 행만 지움. 하루 한 번 정리 작업. 메시지는 「위치를 보냈어요」로 남음

route_shares 1단계

경로 공유 카드의 기록. messages(kind = ROUTE)와 1:1. 공유를 시작할 때, 목적지를 바꿀 때, 끝날 때만 씀.

message_idPK FKBIGINTmessages.id
방 · 보낸 사람은 messages 에서 조인. 「이 방에 진행 중인 내 공유」는 시작할 때만 찾고, 진행 중엔 서버 메모리에 둠. INDEX(state)
stateVARCHAR(8)ACTIVE · ARRIVED · STOPPED
dest_name · dest_addrVARCHAR목적지(바뀌면 덮어씀)
dest_lat · dest_lonDOUBLE지도의 깃발
from_addrVARCHAR(120)출발 주소
from_lat · from_lonDOUBLE출발 좌표. 차 위치를 아직 못 받았을 때 지도에서 출발점으로 씀
ended_atTIMESTAMP NULL도착 · 종료 시각. 진행 중이면 NULL. 시작 시각은 messages.created_at

실시간 상태 (DB 아님) 1단계

경로 공유 중 계속 바뀌는 값. 서버 메모리 Map<message_id, LiveRoute>에 마지막 값만 두고, 받자마자 WebSocket으로 전달. 새로 연결한 폰에는 이 마지막 값을 줌. 서버를 여러 대로 늘리면 Redis로 옮김.

car_lat · car_londouble차의 지금 위치(지도의 프로필 마커)
remain_sec · pctint남은 시간(초) · 진행률(0~100)
eta_atInstant도착 예정
trafficList[[from,to,"fast"],…]. null = 정보 없음
updated_atInstant오래 안 오면(예: 1분) 「연결 끊김」 표시용

friendships 1단계

내 친구 목록. 한쪽 방향(카카오톡처럼 내가 추가하면 내 목록에만). 1단계는 조회만(가계정 둘이 서로 친구로 미리 들어감). 번호로 찾아서 추가는 2단계.

user_idPK FKBIGINT추가한 사람
friend_idPK FKBIGINT추가된 사람
created_atTIMESTAMP

문자 인증번호. 가입 · 아이디 찾기 · 비밀번호 재설정.

Redis (DB 아님) 2단계

만료되는 값과 실시간 값. 1단계는 서버 메모리로 대신하고, AWS에 올릴 때 Redis로 옮김. 재시작해도 남게 AOF 저장을 켬.

이렇게 나눈 이유

읽음은 room_members.last_read_msg_id 한 칸. 메시지마다 「누가 읽었나」를 저장하면 메시지 수 × 멤버 수만큼 행이 늘어난다. 카카오톡처럼 「어디까지 읽었나」만 두면 멤버당 한 칸이고, 안 읽은 사람 수는 계산으로 나온다.
messages는 공통 칸만, 종류별 내용은 따로. 대부분이 글이라 위치 · 경로 칸을 messages에 두면 거의 모든 행이 빈 칸(NULL)이 된다. 공통 + 종류별 테이블로 나누면 JPA @Inheritance(JOINED)와 그대로 맞고, 위치 보관 기간이 지나면 message_locations 행만 지우면 된다. 방 메시지를 가져올 때 LEFT JOIN 두 번이 늘지만 한 번에 50개라 부담이 작다 [추정].
차 위치 · 남은 시간 · traffic은 DB에 안 둠. 5초마다 바뀌는 실시간 값이라 저장하면 UPDATE만 계속 쌓이고, 차 위치가 디스크에 남는다. 서버 메모리에 마지막 값만 두고 WebSocket으로 바로 넘긴다. 서버가 재시작돼 사라져도 차가 5초 안에 다시 보낸다.
경로선(Directions 결과)은 어디에도 없음. 네이버 Maps 약관 제7조 ⑨⑪(저장 · 재사용 금지). 차 위치(pos)와 목적지만 두고, 폰이 지도를 열 때 직접 호출한다.
「이 방에서 간 곳」은 route_shares로 못 대신함. 경로 안내를 해도 공유는 안 할 수 있어서(목적지 창: 「안내 중에 목적지를 바꿔도 공유는 시작되지 않아요」) 경로 공유 기록에서 뽑으면 빠지는 곳이 생긴다. 그래서 따로 두고, 위치 기록이 쌓이지 않게 방마다 3개만 남긴다. 순서는 id로 충분해서 시각 칸을 두지 않는다.
앱에만 두는 것. 즐겨찾기, 내 최근 목적지(navRecent), 지금 안내 중인 목적지, 내비 검색 결과, 설정(실제 내비 쓰기 등)은 기기 상태라 서버에 안 둔다.

정한 것

  1. 현재 위치 보관: 1년. 지나면 message_locations 행만 지움(하루 한 번).
  2. 이 방에서 간 곳: 방마다 3개, 이름 + 주소가 같으면 같은 곳.
  3. 친구: 한쪽 방향.
  4. 시스템 메시지: 서버가 만들어 messages(kind = SYSTEM)에 저장(2단계 방 만들기 · 초대부터).
  5. DB: PostgreSQL.
